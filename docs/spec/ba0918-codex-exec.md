# ba0918-codex-exec 仕様

## 目的

タスクのやり方を決めるスキルと、そのタスクを誰に実行させるかを分けて、小さなスキルの
組み合わせで複雑な作業を組み立てられるようにする。このスキルはその「誰に実行させるか」の
側の 1 つで、Codex CLI を通して、別の提供元のモデルにタスクを 1 つ実行させる。

一文でいえば: 呼び出し元が用意したプロンプトと環境で `codex exec` を 1 回実行し、
終了コード、出力のファイル、変更一覧を返す。

このスキルは [実行役スキル](../../PROJECT.md#glossary) である。プロンプトの中身を書かず、
結果の良し悪しも判定しない。サンドボックスのモード、どの worktree で動かすか、どの権限を
与えるかといった環境の用意は、呼び出し元（メインセッション）の責務であり、このスキルは
自分からは決めない。

[ba0918-opencode-exec](ba0918-opencode-exec.md) の Codex 版で、要件の大半は同じ形をとる。
違いは [opencode 版との違い](#opencode-版との違い) にまとめる。各スキルは単体で完結させるため、
この仕様も opencode 版を参照せずに読めるように書く。

用語（実行役スキル、前置きのコマンド、変更一覧）の定義は `PROJECT.md` の Glossary 節にある。

## opencode 版との違い

| 項目 | opencode 版 | この Codex 版 | 理由 |
|---|---|---|---|
| サンドボックス | CLI にない。前置きのコマンドかエージェント設定で呼び出し元が用意する | `--sandbox` を任意の入力として受け取り、渡されたときだけそのまま付ける。既定は付けない | Codex は CLI で読み取り専用にできるが、読み取り専用にするかはタスク次第のため、呼び出し元が決める |
| 権限の設定 | エージェント名（`--agent`） | 設定プロファイル（`--profile`） | Codex で設定のまとまりを切り替える手段がプロファイルのため |
| 権限の確認 | `--auto` で、設定で拒否されていない権限を自動で許可する | 付けるフラグはない。`codex exec` は権限の確認の要求をすべて拒否する | `codex exec` の実装が、確認の要求を常に拒否するため（2026-09-27 に codex リポジトリ main の `codex-rs/exec/src/lib.rs` をドキュメントのインデックス経由で確認。インストール済みの 0.157.1 では未確認） |
| プロンプトの渡し方 | ファイルの中身を 1 つの引数で渡す | プロンプトの引数に `-` を渡し、ファイルを標準入力につなぐ | 先頭が `-` のプロンプト、長すぎるプロンプト、シェルの展開の問題が起きないため |
| 版の確認 | メジャー版が 2 でなければ実行しない | コマンドが見つかるかだけを確かめる | Codex には、フラグの意味が変わった版の境目として拒むべきものが見当たらないため |
| git の管理外 | 特別な扱いはない | `--skip-git-repo-check` を付ける | Codex は、これがないと git の管理外で実行を拒むため |
| stdout | 既定の出力（`--format json` を使わない） | 既定の出力（`--json` を使わない）。stdout には最終メッセージだけが入る | Codex の既定の出力は、最終メッセージだけを stdout に書き、それ以外を stderr に書くため（2026-09-27 に main の同じファイルのコメントで確認。0.157.1 では未確認） |

## 要件

各要件の確認方法は、末尾の [人手確認チェックリスト](#人手確認チェックリスト) の項目番号で示す。
このスキルはコードではなく指示文書なので、確認は、人が実際にエージェントで試す手順と、
公式バリデータ（`agentskills validate`）で行う。モデルを繰り返し走らせる自動測定は必須にしない。

### 移植性

Codex CLI と git は、このスキルの扱う対象と変更一覧の手段なので本文に書く。それ以外は、
特定のエージェント、モデル、実行環境の仕組みに依存しない自然言語で書く。他のスキルにも
依存しない。環境ごとの値（サンドボックスのポリシーファイルのパス、モデル名の既定値、
ホームディレクトリ配下のパス）や、特定の外部サンドボックスの名前は本文に書かない。

- 成功条件: `agentskills validate ./skills/ba0918-codex-exec` が通る。本文に Codex と git
  以外の固有のツール名や API 名、絶対パス、特定の利用者の環境の値が現れない（人が本文を読んで
  確認する）（C-01）。
- 反例: 本文にサンドボックスのポリシーファイルの絶対パスが書かれている。「Bash ツールの
  run_in_background で」と書かれている。

### 実行してよい条件

実行するのは、ユーザーが名指ししたとき、またはユーザーが用意した指示（割り当て表、
ローカルの組み合わせスキル、指示ファイルなど、形は問わない）がこの実行役を名指ししたとき
だけである。タスクのスキルが読み込まれた、Codex の話題が出た、というだけでは実行しない。
この条件を、説明文（description）と本文の両方に書く。

- 成功条件: 説明文と本文の両方に、名指しされたときだけ実行することが書かれている（人が読んで
  確認する）。Codex について質問しただけの会話で `codex exec` が実行されない。ユーザーの
  直接の名指しと、指示ファイルに書いた名指しの両方で実行される（C-02）。
- 反例: 「codex exec ってどう使うの？」という質問に対して `codex exec` を起動する。

### 外部への送信の明示

作業ディレクトリの内容と、プロンプトの中身が、選んだモデルの提供元に送られる。
名指しされた時点で送ってよいと判断済みとみなし、実行前に改めて確認しない。そのかわり、
送られることを説明文と本文の両方に書く。

- 成功条件: 説明文と本文の両方に、内容が選んだモデルの提供元に送られることが書かれている
  （人が読んで確認する）。名指しされた実行で、送信の確認を挟まずに実行が始まる（C-02）。
- 反例: 説明文に送信のことが書かれておらず、利用者が入れてから初めて気づく。

### 呼び出し元が渡すもの

| 渡すもの | 必須か | 内容 |
|---|---|---|
| プロンプトのファイル | 必須 | それだけで完結したタスクの指示 |
| モデル | 必須 | Codex が `--model` で受け付けるモデル名 |
| 作業ディレクトリ | 任意 | 既定は現在の作業ディレクトリ。worktree を用意したならそのパス |
| サンドボックスのモード | 任意 | `read-only`、`workspace-write`、`danger-full-access` のどれか。既定はなし（Codex の設定に従う） |
| プロファイル | 任意 | Codex の設定プロファイル。設定を効かせるときに使う。既定はなし |
| [前置きのコマンド](../../PROJECT.md#glossary) | 任意 | サンドボックスの起動などのコマンド列。単語の並び（引数のリスト）で受け取る |
| コマンド名 | 任意 | 既定は `codex` |
| 変更禁止 | 任意 | この実行で作業ディレクトリを変えてはいけないこと。既定はなし |
| 時間の上限 | 任意 | 既定はなし |
| 出力の置き場所 | 任意 | 既定は一時ディレクトリ。まだ存在しなければスキルが作る |

渡されていないものをスキルが選ばない。サンドボックスや確認を緩めるフラグ
（`--dangerously-bypass-approvals-and-sandbox` など）をスキルが付けることはない。

次のときは実行せず、何が足りないか・何がおかしいかを返す。

- 必須のものが渡されていない
- プロンプトのファイルが存在しない、空である、または読めない
- 作業ディレクトリが存在しない
- 出力の置き場所が作業ディレクトリを含むリポジトリの中にある。作業ディレクトリが git の管理下に
  なければ、作業ディレクトリの中にある（黙って別の場所に変えると、呼び出し元がファイルを
  見つけられなくなるため）

モデル、サンドボックスのモード、プロファイルの書き方はスキルでは検査しない。誤っていれば
Codex がエラーを返し、それを結果として返す。

- 成功条件: モデルを渡さずに呼ぶと、実行されず、モデルが足りないと返る。存在しないプロンプトの
  ファイルを渡しても同様に返る。出力の置き場所に作業ディレクトリの中を渡すと、実行されず、
  その理由が返る（C-03）。
- 反例: モデルが渡されないとき、スキルが自分で適当なモデルを選んで実行する。サンドボックスの
  モードが渡されないとき、スキルが `read-only` を付ける。作業ディレクトリの中を指定された
  出力の置き場所を、黙って一時ディレクトリに変える。

### 実行前の確認

実行の前に次を行う。

1. 前置きのコマンドを付けてコマンド名の `--version` を実行し、コマンドが見つからなければ、
   実行せずにその旨を返す。前置きを付けるのは、サンドボックスの中で別のものが解決される
   食い違いを防ぐためである。
2. 作業ディレクトリが git の管理下なら、それを含むリポジトリ全体の状態を記録する。記録するのは、
   その時点のコミット（HEAD）、変更のあるファイル・無視されていない未追跡のファイルの一覧、
   それぞれの中身を比べられる値（ハッシュ）である。記録は出力の置き場所のファイルに書き、
   会話には置かない。git の管理下でなければ記録しない。

- 成功条件: 存在しないコマンド名を渡すと、実行されず、コマンドが見つからないことが返る（C-04）。
- 反例: 前置きの外でコマンドを確認し、サンドボックスの中では見つからずに失敗する。

### コマンド

実行するコマンドは次の形である。

```
[前置きのコマンド] <コマンド名> exec --model <モデル> [--sandbox <モード>] [--profile <プロファイル>] [--skip-git-repo-check] - < <プロンプトのファイル>
```

- 作業ディレクトリで実行する。
- 前置きのコマンドは解釈せず、受け取った単語の並びを、並びも中身も変えずに前に付ける。
  1 本の文字列として渡されたときも、スキルが空白で分けたりシェルに解釈させたりせず、1 つの単語として
  そのまま付ける。
- プロンプトは、引数に `-` を渡し、ファイルを変えずに標準入力につないで渡す。プロンプトを
  引数でも渡すことはしない（両方あると、Codex は標準入力を引数の後ろに別のブロックとして足す）。
  ファイルは、何を頼んだかの記録として残す。
- 前置きのコマンドが標準入力を Codex まで通さない場合、Codex は空のプロンプトを受け取る。
  そのときの Codex の振る舞いが、そのまま結果になる（失敗するかは未確認）。
- `--skip-git-repo-check` は、作業ディレクトリが git の管理下でないときだけ付ける。
  管理下では Codex 自身の確認を残す。
- `--sandbox` と `--profile` は、渡されたときだけ、渡された値のまま付ける。
- stdout と stderr は、出力の置き場所に、実行ごとに異なる名前（日時と乱数を含む）のファイルで
  書く。既存のファイルは上書きしない。
- stdout は Codex の既定の出力形式のまま書く（`--json` は使わない）。

- 成功条件: 前置きのコマンド、サンドボックスのモード、プロファイルを渡した実行で、実際に起動された
  コマンドが上の形になっている（引数と標準入力を表示してから本物に渡す前置きのコマンドを使って
  人が確認する）。引用符や `$` を含むプロンプトと、先頭が `-` のプロンプトが、そのままの文字列で
  届く（C-05）。
- 反例: サンドボックスのモードが渡されないのに `--sandbox` を付ける。プロンプトを引数と標準入力の
  両方で渡す。前置きのコマンドの中身を書き換えたり、一部だけを使ったりする。プロンプトの中の
  `$HOME` が展開されて届く。

### 実行と待機

実行は、セッションが終了を待てる形で行い、終了するまで待つ。長い実行（数十分）でも、
途中で状態を確かめるために実行を止めたり起動し直したりしない。

時間の上限が渡されたときだけ、それを超えたら、このスキルが起動したプロセスとその子孫を
すべて止める。前置きのコマンドだけを止めて、中の Codex が書き込みを続けるのを防ぐためで
ある。ほかのプロセスは止めない。止めた後で変更一覧を作り、結果には時間切れであることを明記
して、そこまでの stdout・stderr のファイルと変更一覧を返す。

前置きのコマンドによっては、Codex がこのスキルの起動したプロセスの子孫にならない。スキルからは
子孫の外で動く Codex が見えないため、時間切れで止めたときは、前置きのコマンドが渡されていたか、
止めた後に子孫が残っていないことを確かめられなかったなら、Codex がまだ動いていて、変更一覧の
後にも書き込みが続くかもしれないことを、時間切れの明記とあわせて結果に書く。

- 成功条件: 数分かかる調査を頼み、途中で止めたり起動し直したりせずに、終了後に結果が返る
  （C-09）。上限を短く渡した実行で、上限を過ぎたところで止まり、時間切れと明記された結果が
  返る。前置きのコマンドの中の Codex も止まっている。同時に動かしておいた別の Codex の
  プロセスは止まらない（C-06）。
- 反例: プロセス名で Codex をまとめて止める。前置きのコマンドだけを止める。時間切れを通常の
  終了として返す。前置きのコマンドが渡されていた実行で、止まったものとして返す。

### 変更一覧

実行が終わったら（終了コードが 0 でも 0 以外でも、時間切れでも）、実行前の記録と比べて
[変更一覧](../../PROJECT.md#glossary) を作る。サンドボックスのモードが `read-only` でも作る
（前置きのコマンドや設定が書き込みの範囲を広げうるため、モードだけでは変更がないと言えない）。

- 対象は、作業ディレクトリを含むリポジトリ全体の、git から見えるファイル（追跡中のファイルと、
  無視されていない未追跡のファイル）である。git で無視されたファイルは対象外で、そのことを
  結果に書く。
- 実行前と実行後の状態だけを比べる。実行前から変更のあったファイルも、中身が変わっていれば
  入れる。実行中に変わって元に戻ったファイルは入れない。
- HEAD が実行前から動いていれば、そのことと、前後のコミットの間で変わったファイルを入れる。
- 誰が変更したかは区別しない。区別が要るなら、呼び出し元がディレクトリを分ける。

変更は戻さない。

- 成功条件: 実行前から未コミットの変更があるファイルを、プロンプトでさらに書き換えさせると、
  そのファイルが変更一覧に入る。新しいファイルを作らせると、それも入る。ファイルを変えて
  コミットまでさせると、HEAD が動いたことと、そのファイルが入る（C-07）。
- 反例: `git status` の表示が前後で同じだからといって、中身の変わったファイルを変更一覧から
  落とす。`read-only` で実行したからといって変更一覧を作らない。変更を見つけて自動で元に戻す。

### 返すもの

結果として次を返す。要約や良し悪しの判定はしない。

- 終了コード（時間切れのときはそのこと）
- stdout のファイルのパス（既定の出力形式では、Codex の最終メッセージだけが入る）
- stderr のファイルのパス
- 変更一覧と、それが「開始から終了までにリポジトリの git から見えるファイルで起きた変更で、
  誰の変更かは区別せず、無視されたファイルは含まない」ものであること（git の管理下でなければ、
  検出できなかったこと）
- 権限の注記: 使ったサンドボックスのモード（渡されていなければ、Codex の設定に従ったこと）と、
  `codex exec` は権限の確認の要求をすべて拒否するため、サンドボックスが許さない操作は確認を
  待たずに失敗すること

前置きのコマンド自体の失敗と Codex の失敗は区別しない。どちらも終了コードと stderr で返す。

変更禁止が渡された実行では、ほかの結果より先に次を伝える。

- 変更一覧が空でなければ、変更が起きたこと
- git の管理下でなければ、変更を検出できないこと

- 成功条件: 変更禁止を渡してファイルを書き換えさせる実行で、結果の最初に変更が起きたことが
  書かれている（C-07）。git の管理下でない場所で変更禁止を渡すと、結果の最初に検出できない
  ことが書かれている（C-08）。どの実行の結果にも上の 5 点がある（C-05）。
- 反例: stdout の内容を要約して「問題はありませんでした」と返す。変更が起きたこと、または
  検出できないことを、出力の説明の後ろに埋もれさせる。

### 出力ファイル

stdout・stderr のファイルと実行前の記録は、出力の置き場所に置く。出力の置き場所がまだ存在
しなければ、スキルが作る。スキルはこれらのファイルを消さない。消すのは呼び出し元かユーザーで
ある。Codex が自分のホームディレクトリに残すセッションのファイルは、Codex の管理に任せる。

- 成功条件: 出力の置き場所を渡さない実行で、ファイルが作業ディレクトリの外にでき、実行後も
  残っている。同じ置き場所で 2 回実行して、1 回目のファイルが上書きされていない（C-05）。
- 反例: 結果を返した後にファイルを消す。2 回目の実行が 1 回目の stdout を上書きする。

### README

`README.md` のスキル一覧に ba0918-codex-exec を加える。あわせて次を書く。

- Codex CLI が必要なこと。別名で入れている場合はコマンド名を渡せること
- 作業ディレクトリの内容とプロンプトが、選んだモデルの提供元に送られること
- サンドボックスのモードはスキルが決めないこと。読み取り専用にしたいなら、呼び出し元が
  `read-only` のモードを渡すか、同等の設定を持つプロファイルや前置きのコマンドを渡すこと

特定の外部サンドボックスのツールは名指ししない。

- 成功条件: README に上記 3 点があり、特定の外部サンドボックスのツールの名前がない（人が読んで
  確認する）（C-08）。
- 反例: README から、サンドボックスのモードがスキルの責務でないことが分からない。

## 保存する状態と寿命

| 状態 | 置き場所 | 寿命 |
|---|---|---|
| 実行前の git の状態の記録 | 出力の置き場所 | 呼び出し元かユーザーが消すまで。スキルは消さない |
| stdout・stderr のファイル | 出力の置き場所（既定は一時ディレクトリ） | 呼び出し元かユーザーが消すまで。スキルは消さない |
| プロンプトのファイル | 呼び出し元が置いた場所 | 呼び出し元が決める。スキルは消さない |
| Codex のセッションのファイル | Codex のホームディレクトリ | Codex の管理に任せる |

## 外部依存

- Codex CLI（必須）
- git（任意。無ければ変更一覧を検出できない）
- 前置きのコマンドで渡されるもの（呼び出し元が用意する。スキルは知らない）

| 実行の依頼 | なし（名指しそのものが判断） | どの実行役で、どのモデルで、どのサンドボックスのモードと環境で動かすか |
| 変更禁止の実行で変更が起きた | 結果の最初にある変更一覧 | 変更をどうするか（スキルは戻さない） |
| 変更禁止の実行で検出できない | 結果の最初にある、検出できないことの明記 | 結果をどこまで信用するか |
| 時間切れ | 時間切れの明記と途中までの出力 | 続けるか、やり直すか |

## 作らないもの

- サンドボックスのモードの既定値、worktree の用意、権限の設定。環境の用意は呼び出し元の責務である。
- タスク用のプロンプトの作法（レビューの観点、指摘の書式など）と、結果の判定・分類。
- `codex exec resume` など、既存のセッションを続ける実行。
- 最終メッセージの別ファイル（`--output-last-message`）。既定の出力では stdout が最終メッセージ
  だけなので、足りる。
- 変更の自動の取り消し。
- git で無視されたファイルの変更の検出。

## 却下した案

- サンドボックスのモードの既定を `read-only` にする: 書き込むタスクで毎回指定が要り、Codex の設定で
  決めている既定も上書きしてしまうため。
- サンドボックスの入力を持たず、プロファイルか前置きのコマンドだけで制御させる: Codex が CLI で
  直接指定できるものを、わざわざ遠回りさせることになるため。
- プロンプトを引数で渡す: 先頭が `-` のプロンプトと長すぎるプロンプトを断る必要が生じ、シェルの
  展開にも気を配る必要があるため。
- `--output-last-message` で最終メッセージのファイルも作る: 既定の出力で stdout が最終メッセージ
  だけになり、結果の項目を増やすだけになるため。
- `--json` で出力する: 判定は呼び出し元が行い、既定の形式で読めれば足りるため。
- `--ephemeral` を常に付ける: セッションを後から見返す手段を呼び出し元から奪うため。必要なら
  プロファイルなどで呼び出し元が決める。
- `--skip-git-repo-check` を常に付ける: git の管理下での Codex 自身の確認まで外してしまうため。
- 版の番号で実行を拒む: 拒むべき版の境目が見当たらないため。
- モデルを任意にして Codex の設定に任せる: 送信先の提供元とモデルを呼び出し元が選んだことが、
  送信の判断の前提のため。サンドボックスのモードと違い、既定に任せない。
- 実行前に外部への送信を確認する: 名指しした時点で判断済みであるため。
- 出力ファイルを作業ディレクトリに置く: それ自体が変更一覧に入り、リポジトリも汚れるため。
- 既定の時間上限を持つ: 上限は呼び出し元の都合であり、呼び出し元が渡せば足りるため。

## 人手確認チェックリスト

実際のエージェントで、Codex CLI が使える環境と、git 管理下の作業用リポジトリを使って試す。
各項目は、該当する要件の成功条件を満たすかを見る。

- C-01: `agentskills validate ./skills/ba0918-codex-exec` が通る。本文に Codex と git 以外の
  固有のツール名や API 名、絶対パス、特定の利用者の環境の値、特定の外部サンドボックスの名前がない。
- C-02: Codex について質問しただけの会話で `codex exec` が起動しない。「このリポジトリの
  構成を codex の <モデル> で調べて」と名指しすると、送信の確認なしに実行が始まる。指示
  ファイルに「調査にはこの実行役を使う」と書いた状態で調査を頼むと、同様に実行される。説明文と
  本文に、名指しのときだけ実行することと、内容が提供元に送られることが書かれている。
- C-03: モデルを渡さずに呼ぶ、存在しないプロンプトのファイルを渡す、出力の置き場所に作業
  ディレクトリの中を渡す。どれも実行されずに理由が返る。
- C-04: 存在しないコマンド名を渡し、実行されずにコマンドが見つからないことが返る。
- C-05: 引数と標準入力を表示してから本物に渡す前置きのコマンドと、サンドボックスのモード、
  プロファイルを渡し、引用符と `$` を含み先頭が `-` のプロンプトで実行する。表示されたコマンドが
  [コマンド](#コマンド) の形で、プロンプトがそのままの文字列で標準入力に届いている。結果に 5 点が
  そろい、出力ファイルが作業ディレクトリの外にあって実行後も残っている。同じ置き場所でもう一度
  実行し、1 回目のファイルが上書きされていない。

  入る。変更禁止を渡して書き換えさせ、結果の最初に変更が起きたことが書かれている。どの回でも

  渡せること、内容が提供元に送られること、サンドボックスのモードはスキルが決めず呼び出し元が
  渡すことが書かれ、特定の外部サンドボックスのツールの名前がない。
- C-09: 数分かかる調査を頼み、途中で止めたり起動し直したりせずに、終了後に結果が返る。
